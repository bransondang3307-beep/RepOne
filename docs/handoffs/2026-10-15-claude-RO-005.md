## Review round 1 — RO-006 (Codex) findings addressed

Review: [PR #3 review 5540804748](https://github.com/bransondang3307-beep/RepOne/pull/3) on `1ef8f6f`, verdict
"changes requested" (submitted as COMMENT). Fix commit: "RO-006: fix boundary-checker workspace cycles and restore
controller × SQLite integration test" (`2dae11b`).

**Finding 1 (P2) — workspace imports were not cycle-graph edges.** `scripts/check-boundaries.mjs` skipped every
`@repone/*` import with `continue`, so a cycle through a package's own barrel passed.
- Fix: workspace imports are resolved through each package's `package.json` `exports` (or `main`) to the entry
  file and added as graph edges; existing dependency rules are unchanged. An `@repone/*` import that cannot be
  resolved is now reported. The checker accepts an optional root argument so it can run on fixtures.
- Regression tests: `scripts/check-boundaries.test.mjs` (node:test, 7 cases) — clean workspace incl. `/testing`
  passes; **Codex's exact repro** (self-import through barrel) fails with the cycle path; cycle through the
  `./testing` exports subpath; cross-package cycle; plain relative cycle; unresolvable workspace import; the real
  repository passes. Wired in as `npm run test:scripts`, now the first step of root `npm test` (so `verify` and CI run it).
- Red/green: against the old logic (given only the root argument) **4/7 fail** (all workspace-edge cases);
  new checker **7/7 pass**. Codex's repro in a disposable repo copy: old exit 0 → new exit 1 with
  `cycleA.ts → index.ts → cycleB.ts → cycleA.ts`.

**Finding 2 (P2) — controller × SQLite integration coverage was lost.**
- Fix: `apps/mobile/src/infrastructure/database/__tests__/WorkoutSessionController.sqlite.test.ts` restores the
  original test **verbatim** ("records a live simulated session against SQLite and stops on demand", same fixture as
  `main` @ `d9a7274`) under infrastructure, so the service and its unit tests stay platform-independent. Added one
  more integration test: replayed labelled set through SQLite — raw samples equal the trace in order (incl. a
  non-multiple-of-batch tail), all 10 rep events persisted in order, last row equals the snapshot's last event,
  session ended, summary counts 8 full / 2 partial (synthetic data).
- No existing test removed: the in-memory controller tests in `application/services/__tests__` are unchanged.
- Mutation check: temporarily dropping the last sample of each SQLite batch made **both SQLite integration tests
  fail while all 5 in-memory controller tests still passed** — the restored test covers what the in-memory one cannot.
  Mutation reverted.

**Codex note — "no behaviour change" qualified** in this handoff, the PR description and ADR 0003 (History refresh mechanics).
