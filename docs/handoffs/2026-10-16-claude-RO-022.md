## Objective
RepOne is developed on Windows machines, and RO-021's bugs escaped Linux CI. Add a small Windows test job and keep
the existing Linux CI.

## What changed
- **`.github/workflows/ci.yml`:** adds one job, `windows` ("Windows — boundary checker and its tests"):
  - `windows-latest`, `actions/setup-node@v4` with **Node 24**, matching the Lenovo (v24.22). Linux stays on 22, so CI
    now covers both versions.
  - Default git line endings (`core.autocrlf=true` on the runner, as on a default Git for Windows install).
  - `npm run test:scripts --if-present`, then `npm run check:boundaries --if-present`. It uses the same `--if-present`
    pattern as the Linux job, so branches without the checker (today's `main`) pass. The checker becomes active once
    PR #3 merges.
  - **No `npm ci`**: the checker and its tests import only Node built-ins. I checked this on Linux in clean checkouts
    with no `node_modules`.
  - `timeout-minutes: 10`.
- The **Linux `verify` job and the `handoff` job are byte-for-byte unchanged.** Triggers and concurrency are unchanged.
- `TASKS.md`: RO-022 row and details; next free ID → RO-023.
- No ADR change. ADR 0004 §5 describes the Linux CI; this job adds to it without changing any decision.

## Known limitations / risks
- **Cost:** Windows runner minutes are billed at a higher rate than Linux on private repos (2× under GitHub's
  published multiplier; check the account's billing page). COST_LINE
- **Scope is deliberately small.** On Windows it covers `scripts/` only, not typecheck or Jest. Running the full
  `npm run verify` on Windows needs `npm ci`, which took 78–192 s per job in RO-021 (runs 38933126592 and 38933872724).
  That would cost about 4–5× more and is **not added** without a further owner decision.
- Until PR #3 merges, the job is a no-op on `main` and on branches without the checker.
- `actions/checkout@v4`/`setup-node@v4` show GitHub's "Node.js 20 is deprecated" warning on runners. This is the same
  as the existing Linux job; upgrading the action versions is a separate change.
- `TASKS.md` conflicts trivially with PRs #5 and #9 on the "Next free ID" line and the rows after RO-018.
