## Objective
Reproduce RO-011 finding 1 on native Windows. If confirmed, fix path normalization in
`scripts/check-boundaries.mjs` without changing the dependency rules, and add regression coverage that
would have caught it. Keep this separate from RO-008, which is documentation only.

## Finding (reproduced on native Windows)
`path.relative()` returns `\`-separated paths on Windows, while `layerOf()`, `isLayerIndex()`, `isTest()` and the
diagnostics are written with `/`. On Windows every file was therefore classified as `other`, so the layer
rules were **silently skipped**. The checker printed "boundaries OK" even for real violations. In addition,
cycle diagnostics contained `\`, so 4 of the 7 checker tests failed. As a result, `npm run verify` failed on Windows.

Antigravity reviewed `40d4a22` by reading the code without executing it. My container is Linux, so the native
check ran on GitHub-hosted **`windows-latest`** runners: Windows Server 2025 Datacenter 10.0.26100, `core.autocrlf=true`,
the same `npm ci` → `npm run verify` path the owner uses. This is real Windows, but **not the owner's Lenovo**
(Windows 11, Node 24.22). The Lenovo commands are below.

## What changed
- **`scripts/check-boundaries.mjs`** (PR #3, `30e2dd3`): adds a single helper,
  `repoPath = (abs) => relative(ROOT, abs).split(sep).join('/')`, used at the 3 call sites (layer classification,
  import-target classification, cycle diagnostics). The dependency rules are unchanged.
- **Regression test** `scripts/check-boundaries.test.mjs` case 8 (PR #3, `30e2dd3`): runs the real checker with the
  test-only preload `scripts/test-support/simulate-windows-paths.mjs`, which makes `path.relative`/`path.sep` behave
  like Windows on Linux CI. It asserts that a package-dependency violation, a feature→feature violation and a cycle are
  all reported with `/` paths and no `\`.
- **Preload fix** (PR #3, `6f48f1d`), **found only by the native run**: on Windows `node:path` *is* `path.win32`,
  so the wrapper `path.relative = (f, t) => path.win32.relative(f, t)` called itself, causing a stack overflow in the
  checker. Test 8 failed and `npm run verify` exited 1 on `30e2dd3` (Node 22 and 24). The preload now captures
  `path.win32.relative`/`sep` before patching. The checker is unchanged.
- **`TASKS.md`**: RO-021 row and details; next free ID set to RO-022.
- **Temporary harness** (`.github/workflows/ro-021-windows-repro.yml`, `.github/ro-021/windows-repro.mjs`): ran
  the checks on Windows and reported through annotations, because job logs can't be downloaded from this container.
  It was **removed again** in the final commit, so this PR does not add it to `main`.
